# 切后台挂起同步与重试、回前台立即恢复，V1 不接入推送与系统通知

在 Android 切入后台或锁屏时，通信层主动中止当前 `/sync` 长轮询并暂停「重试队列」计时器，回到前台或设备唤醒时立即清零退避等待、携带「同步游标」恢复增量 `/sync` 与队列重放；V1 在 Android 与 macOS 双端均不接入后台推送、不驻留后台服务，也不发送系统级通知。

## Considered Options

- 切后台时不主动干预，任由 `/sync` 与重试队列在后台被系统冻结或超时报错并累加指数退避。否决：Android 后台会冻结 WebView 网络与定时器，若不主动挂起并在回前台时清零退避，Owner 切回应用后会因僵死连接或残留退避计时而卡顿等待。
- Android 接入 FCM / UnifiedPush 或启动常驻前台服务（Foreground Service）做后台实时推送通知。否决：接入推送需要自建 Homeserver 额外部署配置 Push Gateway；常驻前台服务不仅持续耗电并占用系统通知栏，还会打破 ADR-0005 与 ADR-0010 将通信层与 `access token` 留在 WebView IndexedDB 内的架构边界。
- Android 不做后台推送，但在 macOS 窗口失焦时弹出桌面系统通知或设置 Dock 角标。否决：V1 保持双端通知心智一致，不申请系统通知权限、不设图标角标，统一通过打开或切回应用时的 Topic 列表「未读」指示与最近活动排序呈现新消息。

## Consequences

- **切后台挂起与回前台立即恢复**：
  - 在 Android 上当应用切入后台或锁屏（页面变为不可见 `hidden`）时，通信层主动中止当前挂起的 `/sync` 长轮询请求，并暂停「重试队列」的退避计时器；后台挂起导致的中断不计入失败退避次数。
  - 当应用回到前台可见（或桌面端从系统休眠/断网中恢复）时，立即清零退避等待，携带 IndexedDB 中已有的「同步游标」发起增量 `/sync`，并立刻唤醒「重试队列」按进入重试队列的顺序继续重放；若当前正打开某条 Topic，新同步到的消息出现在屏幕上后按既有规则前移「已读位置」。
  - 若 Android 后台期间 WebView 进程被系统回收，重新打开应用时直接从 IndexedDB 读取已持久化的 `access token`、「同步游标」、「本地时间线」、「草稿」与「重试队列」，无缝执行增量 `/sync` 恢复与队列重放。
- **不接入后台推送与系统通知**：
  - V1 在 Android 端不接入 FCM 或 UnifiedPush，不启动常驻后台/前台服务。
  - V1 在 Android 与 macOS 双端均不申请系统通知权限、不弹出系统级横幅/声音通知、不设置应用图标或 Dock 未读角标；新消息（含 Hermes 定时任务主动投递）统一在前台通过 Topic 列表行的「未读」指示与最近活动排序呈现。
