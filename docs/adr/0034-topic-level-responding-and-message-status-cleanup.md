# 「正在回应」收敛为 Topic 级无文字动效并自动自愈，移除未确认转圈与处理结果徽章

「正在回应」由消息级文字提示收敛为 Topic 级无文字单色三点动效（对话时间线末尾与 Topic 列表行统一无可见文字），并引入异常自愈机制避免悬空 `👀` 永久卡死；同时移除对话气泡与 Topic 列表行两处的**未确认**转圈标识，以及绑定 Agent 标在 Owner 消息上的 `✅`/`❌` 处理结果徽章。本决定修订 [ADR-0008](./0008-no-thinking-tool-panel.md)、[ADR-0013](./0013-unconfirmed-spinner-failed-exclamation.md)、[ADR-0019](./0019-topic-list-row-unconfirmed-failed-no-preview.md)、[ADR-0020](./0020-topic-list-unread-indicator-and-pinned-header.md)、[ADR-0026](./0026-tailwind-shadcn-and-grok-monochrome-theme.md) 与 [ADR-0032](./0032-topic-list-latest-message-preview.md)。

## Considered Options

- **继续将失败操作组（`⋯` + `!`）置于 Owner 气泡左侧、将列表红叹号置于第一行时间戳左侧**：否决。移除未确认转圈后，气泡左侧孤立放置两个小图标在移动端会挤压气泡宽度且与气泡底部附属区视觉割裂；列表第一行时间戳左侧插红叹号会打破整列时间戳的右缘对齐轴，而第二行右侧已有专门的右轨状态槽（时刻正下方）。
- **保留消息级「正在回应」文字并仅依赖 `👀` 撤回结束状态**：否决。Hermes 完成后会延迟 5 秒撤回 `👀`，且在被取消（`CANCELLED`）或进程崩溃/重启时永不撤回 `👀` 也不补发终结表情，旧规则会导致 Topic 永久卡在「正在回应」；而处理期间 Hermes 还会发出普通 `m.room.message` 工具进度与流式编辑，不能一出现 Agent 消息就误判结束。
- **对话页用无文字动效但 Topic 列表行保留 `• 正在回应` 文字**：否决。列表行与对话页统一使用无文字单色三点动效更简洁一致，并能避免文字挤占窄屏列表预览宽度；无障碍语义统一通过 `aria-label="正在回应"` 保留。
- **隐藏 `✅` 但保留 `❌` 徽章，或在超时/异常时展示显式异常告警态**：否决。处理结果 `✅` 与 `❌` 均为 Hermes 协议级反馈，隐藏两者可保持对话界面干净，仅保留审批/选择器操作按钮及其他非状态 reaction；异常收敛以静默自愈为主，避免叠加误报横幅，报错内容由 Agent 正文回复承载。
- **保留气泡或列表行上的未确认转圈**：否决。正常网络下消息确认极快，瞬时转圈反而带来视觉闪烁；底层重试队列、不提前改列表时刻与排序、不推进已读位置等机制保持不变，仅在永久**失败**时显示红叹号 `!` 供 Owner 重发或丢掉。

## Consequences

- **移除未确认转圈，保留失败红叹号**：对话内 Owner 气泡旁与 Topic 列表行均不再渲染未确认转圈（及其无障碍 `未确认` 指示）；未确认消息在重试队列中的持久化、重放、预览展示、不提前改写列表时刻与排序、不算未读及不推进已读位置的规则继续生效；永久**失败**态的红叹号 `!` 完整保留并调整布局：对话内放在失败气泡下方右对齐（`⋯` + 红叹号 `!`，点红叹号原样重发，点 `⋯` 打开仅含「丢掉」的菜单），Topic 列表行放在第二行右侧（时刻正下方与 `正在回应` 三点动效正交并列），第一行右侧保持纯粹的时间与 `置顶` 对齐轴。
- **屏蔽处理结果 reaction 徽章**：屏蔽绑定 Agent 标在 Owner 消息上的 `✅` 与 `❌`（均忽略 `\uFE0F` 变体选择符），不再渲染为气泡下方徽章；Agent 消息上的审批与选择器操作按钮及其他普通 reaction 不受影响。
- **Topic 级无文字「正在回应」展示**：
  - 对话页内移除挂在单条 Owner 气泡下的「正在回应」文字，改为在时间线末尾、左对齐 Agent 文档流一侧渲染一条独立的单色三点呼吸/跳动动效（遵循 [ADR-0026](./0026-tailwind-shadcn-and-grok-monochrome-theme.md) 单色语义，`motion-reduce` 降级静止，无可见文字，保留 `role="status" aria-label="正在回应"`）。
  - Topic 列表行第二行右侧同步移除「正在回应」文字，改为统一右轨状态槽（时间戳正下方），在其中正交并列渲染无文字单色三点动效（保留 `aria-label="正在回应"`，与左侧未读圆点视觉区分）与失败红叹号 `!`（无消息预览但存在「正在回应」或「失败」时均渲染第二行）。
- **「正在回应」异常自愈规则**：
  1. **单条终结**：目标消息收到绑定 Agent 的 `✅` 或 `❌`（忽略 `\uFE0F`），或 `👀` / 目标消息本身被撤回时，该 `👀` 立即失效。
  2. **新回合覆盖旧泄漏**：若更晚的 Owner 消息已收到绑定 Agent 的 `✅`/`❌` 终结，此前遗留未撤回的旧 `👀` 一并视为陈旧失效。
  3. **无活动超时兜底**：若仅剩孤立未终结的 `👀`，以该 `👀` 的服务器时间（`origin_server_ts`）与其后绑定 Agent 最新消息或编辑的服务器时间中的较晚者为基准，超过 **5 分钟**无新活动则自动结束「正在回应」（基于服务器时间戳，跨设备一致且刷新/重启不重置计时）。
  4. **环境阻断**：Topic 变为`不可用`或处于需要重登（同步暂停）状态时不展示「正在回应」。
