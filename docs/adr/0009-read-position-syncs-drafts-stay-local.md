# 已读位置跨端同步，草稿只留在本机

已读位置是 Owner 在一条 Topic 里读到的那条消息，各台设备同一份。草稿是还没发出的输入，只留在写下它的那台设备上。已读位置用 Matrix 已有的私有回执和 fully read，不另造 account data。冲突时只采纳更靠后的位置，不用名册那种后写为准。

## Considered Options

- 自造 account data，和名册一样后写为准。否决：已读位置协议里已有，而且不能靠直接写 account data 来设置 fully read。后写为准会让落后的设备把另一台已经读过的位置打回去。
- 只发公开回执，不写 fully read。否决：公开回执会进 Agent 也在的房间。私有回执已经能同步到 Owner 的其他设备，并清掉通知计数。没有 fully read，另一台设备看不到读到哪条消息。
- 已读位置也只留在本机。否决：同一 Owner 在手机上读完，电脑仍会显示未读。
- 草稿也跨端同步。否决：没有稳定规范。后写为准时，另一台设备上的空输入会覆盖还没发出的长草稿。

## Consequences

- 未读不看服务器的通知计数。推送规则可以让计数是 0，消息却还在已读位置之后。
- 有未读时打开停在第一条未读，不跳到最新把未读清掉。
- 后台同步不前移已读位置。没出现在打开的 Topic 屏幕上，就不算读过。
- 草稿的存放，以及已读标记写失败后怎么重试，见 ADR-0010。
