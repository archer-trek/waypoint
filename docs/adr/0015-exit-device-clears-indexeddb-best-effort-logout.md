# 退出这台设备尽量注销，清空 IndexedDB 回到未连接

进列表后主动退出这台设备必须二次确认。向 Homeserver 尽量发送注销请求，无论成败均清空 IndexedDB（丢弃本地时间线、草稿与重试队列），回到首次连接引导页。

## Considered Options

- 退出时仅删除 access token，保留本地时间线和草稿。否决：ADR-0010 已定清应用数据等于重新连接。在未加密与个人 Agent 场景下，退出设备若残留聊天记录与草稿，存在隐私泄漏风险，且换账号再次登录会导致数据交叉污染。
- 强制要求服务端 `/logout` 成功才允许退出。否决：断网或服务端异常时会导致 Owner 被困在应用内无法退出。与首次连接中放弃登录的策略一致，采用“尽量 logout”。
- 退出时调用 Matrix API 删除设备（`DELETE /devices/{deviceId}`）。否决：删除设备通常需要 UIA（交互式用户验证/输入密码），增加不必要的退出阻碍；普通 logout 使 token 失效已足矣，服务端设备名册可在管理端集中打理。
- 点击直接退出，不弹二次确认。否决：退出会丢弃尚未交出的草稿与本地重试队列，属于破坏性操作，必须二次确认防止误触。

## Consequences

- 退出入口放置在全局设置/关于区域以及登录失效提示条中。
- 点击退出强制弹出二次确认弹窗，明确警告“退出将清空这台设备上的本地时间线、未发送草稿与重试队列”。
- 确认后向 `/_matrix/client/v3/logout` 发送请求作废当前 token；网络超时、失败或返回 4xx/5xx 均不阻塞退出，继续执行本地清理。不删除服务端设备记录。
- 彻底清空 IndexedDB 中的所有数据（包括 access token、device_id、同步游标、本地时间线、草稿、重试队列），设备脱离已连接状态。
- 界面回到首次连接引导页；保留上次输入的 Homeserver Base URL 和 Owner 用户标识（localpart 或 user_id）以方便重新连接，密码置空且不保留。
- 另一台设备的已读位置、远端房间以及 Hermes 端的会话记忆均不受影响。
