# Topic 列表行标出未确认与失败，不展示消息正文预览

当一条 Topic 的本地时间线上存在未确认或失败的消息时，列表行用与对话内相同的转圈或红叹号标出；列表行不展示任何消息的正文摘要预览。

## Considered Options

- 列表行不标出未确认与失败，仅在打开 Topic 后的对话气泡旁显示。否决：未确认与失败都不算未读；若 Owner 发完消息立刻切走或在主列表浏览，列表行不标出就会漏掉发送卡住或永久失败的话题。
- 列表行只标失败红叹号，不标未确认转圈。否决：附件上传、断网退避或等待重登期间，未确认可能持续较长时间，列表行用同一转圈能让 Owner 直接看出哪条 Topic 仍有待确认交出。
- 在列表行直接点按红叹号触发重发。否决：一条 Topic 内可能有多条失败消息，且列表行不展示失败气泡上下文；重发与丢掉统一留在打开 Topic 后的气泡上操作。
- 列表行展示最新消息单行正文预览（含或不含未确认/失败正文）。否决：每条 Topic 在诞生时已有 Owner 手写的名字，多 Bot 时副标题已用于显示绑定的 Bot 名字；不放消息正文预览能保持主导航紧凑干净，也无需为未确认或失败消息切换预览文案。

## Consequences

- 列表行仅统计该 Topic 本地时间线上的未确认与失败消息；重试队列中待重放的代发 reaction 和已读位置更新不触发列表行标记。
- 同一列表行最多显示一个发送状态标记，不显示条数。同一 Topic 内同时存在失败与未确认消息时，优先显示需人工介入的红叹号；当未确认与未丢掉的失败消息全部消失时，标记随之消失。
- 列表行上的红叹号仅作状态指示，点击整行仍是打开该 Topic。
- 转圈和红叹号与列表行上的 `正在回应`、`未读`、`不可用` 标签及置顶状态正交共存，互不顶替。
- 未确认与失败消息不提前更新列表行时刻，也不提前改变该 Topic 在列表中的「最近活动」排序位置，待收到服务器确认回声后再按 `origin_server_ts` 更新。
- 列表行不展示已确认、未确认或失败消息的正文预览。
