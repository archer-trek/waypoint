# 服务器不认 token 时顶栏提示，重新登录保留数据并复用 device_id

已连接的设备在收到 `M_UNKNOWN_TOKEN` 时，不弹窗打断，由顶栏静默提示。重新登录仅输入密码，携带原 device_id，保留本地时间线、草稿与重试队列。

## Considered Options

- 引入 MSC2918 Refresh Token 或自动轮转。否决：自建 Matrix 默认 Token 长期有效，`M_UNKNOWN_TOKEN` 属于设备被注销等偶发异常，此时 Refresh Token 亦失效；且会重开 ADR-0011 并加重薄客户端复杂度。
- 出现 `M_UNKNOWN_TOKEN` 时弹出强模态弹窗或整页跳出至登录页。否决：强模态打断当前阅读，整页切走会丢失正在浏览的上下文与编辑中的草稿视觉视野。
- Token 失效或刷新失败直接自动 logout 清库。否决：ADR-0010 已定库留着。静默清库会导致未发送草稿、未确认队列和本地时间线灾难性丢失。
- 重新登录时由服务端重新分配 device_id。否决：每次重新登录都会在 Homeserver 设备列表中累积冗余设备，污染设备名册。
- 允许在重新登录时修改 Base URL 或用户名。否决：修改地址或账号属于换服务器或换身份，会污染本地现有 Topic 映射与时间线。换设备登录属于退出流程。

## Consequences

- 检测到 `M_UNKNOWN_TOKEN` 时，界面绝不主动弹出打断性模态窗，仅在顶栏显示静默提示条。
- 提示条存在期间，Owner 仍可只读浏览本地时间线与已有草稿；新建 Topic、输入框与发送操作禁用，重试队列保持暂停。
- 提示条提供「重新验证」和「退出这台设备」两个入口。「退出这台设备」由专门的退出决策处理，绝不自动静默清库。
- 重新登录表单仅需输入密码；Base URL 与 Owner 的 user_id 由本地 IndexedDB 提供且只读锁定。
- `/login` 请求体一律携带原 device_id；仅在服务端明确拒绝该 device_id 时，才由服务端重新分配并更新本地存储。
- 登录成功后将新 token 写入 IndexedDB，本地时间线与草稿原样保留；重试队列解除暂停并按序恢复发送；同步层以原有同步游标恢复 `/sync`，若游标失效则按 ADR-0010 降级为全量合并同步。
- 密码错误（`M_FORBIDDEN`）仅清空密码框并提示重试，网络异常保留密码并提示重试，任何失败均绝不清空 IndexedDB。
