# Topic 不可用时列表标出标签，顶部横幅说明原因，禁用输入框并保留草稿

Topic 因房间状态异常（加密、多于两人、邀请失败、被 ban 等）进入不可用时，列表行展示不可用标签；打开后顶部横幅提示简要原因并禁止发消息；输入框禁用但保留草稿；改名、改 Description、置顶与删除入口保持一致。

## Considered Options

- 隐藏不可用的 Topic 或移出主列表。否决：ADR-0006 已定不可用 Topic 留在列表中。隐藏会导致已有的重要交流记录无法访问。
- 打开时弹出打断性强模态窗口警告。否决：Owner 打开主要是为了查阅历史记录或执行删除/改名操作，常驻顶部横幅足以提示状态且不打断浏览。
- 禁用输入区时清空草稿。否决：ADR-0009 已定草稿留在写下它的设备上。部分不可用状态（如误拉入第三人、临时 ban）在外部解除后可自动恢复，保留草稿可直接继续编辑发送。
- 不解释具体原因，仅提示统一的“不可用”。否决：Matrix 房间不可用原因差异巨大（被加密、多于两人、Agent 无法加入），一句话点明具体原因能帮助 Owner 判断是外部误操作（可修复）还是已不可逆（应删除）。

## Consequences

- 列表行标题旁显示轻量 `不可用` 标签，整行适度置灰以示区分，点击仍可正常打开 Topic。
- 打开 Topic 后，顶栏下方展示常驻警示横幅，用一句话说明具体原因（如“因房间被第三方加密不可用”、“因房间多于两人不可用”、“因 Agent 无法加入不可用”），并说明无法发送新消息。
- 除加密外，若外部房间状态恢复到仅有 Owner 与绑定 Bot，不可用横幅自动消失，恢复正常状态。
- 底部输入区与发送按钮整体禁用（只读不可编辑），提示占位符显示“Topic 不可用，无法发送消息”；已有未发草稿完整保留在输入框中不丢弃。
- 气泡展示与历史记录不受影响；改名、改 Description、置顶和删除操作入口与交互保持一致。
