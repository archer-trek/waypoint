# Coding Standards

Judgment calls for code review and UI/test changes in `waypoint`. Mechanical rules (unused vars, hooks deps, banned hex colors/raw Tailwind palettes, `leading-none` + `truncate` clipping, `leading-*` before `text-*` precedence, invalid `pt`/fractional `rem` units, icon/asset presence, raw English `body.error` leakage, banned `GLOSSARY.md` terms) are enforced by `eslint.config.js`, `src/waypoint/theme-guard.test.ts`, and `src/waypoint/repo-guards.test.ts`.

## UI, Typography, and Layout

- **Root `rem` baseline & unit hierarchy (`src/App.css`)**: `html, body, #root` sets standard `font-size: 16px` (`1rem = 16px`) alongside `-webkit-font-smoothing: antialiased`. UI chrome and interactive controls (navigation/list rows, headers, buttons, form inputs, timestamps) use explicit integer `px` sizes (`text-[17px]`, `text-[15px]`, `text-[12px]`) or standardized Tailwind classes (`text-sm`, `text-xs`) to avoid floating-point subpixel rounding and optical weight loss across high-DPI displays. Topic conversation messages use `16px` with `line-height: 1.5` and `0.5rem` paragraph margins; headings and inline code inside `.waypoint-markdown` scale via relative `em` units (`h1: 1.45em`, `h2: 1.28em`, `h3: 1.15em`, `h4: 1.05em`, inline-code: `0.875em`). `pt` units are strictly prohibited in stylesheets.
- **Vertical alignment & chrome**: Align narrow mobile list content edges directly to the header brand axis. Keep full-bleed header dividers flush to the viewport edges, and size paired icons optically (e.g. `Plus` spans less of its viewBox than `Settings`).
- **Error copy & form guards**: Write user-facing errors as direct Chinese action guidance (omit `<动作>失败，因为…` boilerplate and raw English server text). Disable primary submit buttons while required fields are empty or whitespace-only, while keeping defensive checks in submit handlers.
- **Icons & native assets**: Keep `src/waypoint/icons.tsx`, `public/favicon.svg`, `src-tauri/icons/`, and `src-tauri/gen/android/app/src/main/res/mipmap-*` visually consistent; regenerate native icon sets together via `npx tauri icon <manifest>`.
- **Streamdown overrides (`MessageBody.tsx` & `src/App.css`)**: Verify custom `components` (`p`, `code`) preserve `li` spacing collapse, `theme-guard.test.ts` CSS resets for `@source`-scanned classes (`border-sidebar`, `p-2`, `gap-2`), `Array.prototype.at` fallback compatibility, and non-overlapping single-line headerless code-block actions (`data-single-line`).
- **Preserve behavioral DOM/ARIA hooks**: Keep `.waypoint-*` semantic classes and `sr-only` landmarks expected by `SidebarView.test.tsx` and `src/waypoint/integration/`.
- **Capsule controls & transition hygiene (`ComposerView.tsx`)**: For absolutely positioned interactive controls within expanding containers (such as `Plus` and send buttons in the composer capsule), anchor them to a constant bottom coordinate reference (`bottom-[9px]` on mobile, `bottom-[7px]` on desktop) across single-line and multiline states rather than shifting between vertical center transforms and bottom offsets. Restrict transitions to `transition-colors` or explicit visual properties; avoid `transition-all` on layout-positioned elements to prevent interpolation jumps.
- **Form dirty-guard ownership (`TopicsWorkspace.tsx` & `ResponsiveFormShell.tsx`)**: Coordinate dirty-form exit confirmation through a single shared guard (`requestGuardedExit` + `DiscardChangesDialog`) across all exit paths (footer cancel, `headerAction`, left-edge swipe, `Escape`, and `onSystemBack`/`popstate` with history depth restoration).
- **Overlay scrollbar architecture (`overlay-scrollbars.ts` & `src/App.css`)**: Keep native scrollbars hidden (`scrollbar-width: none`; `::-webkit-scrollbar` 0px) and render GPU-composited `[data-overlay-scrollbar]` floating thumbs on scroll rather than resizing card gutters or animating pseudo-element `background-color`.
- **Mobile keyboard & viewport strategy (`index.html`, `production.ts`, `viewport-lock.ts`, & `MainActivity.kt`)**: `index.html` sets `interactive-widget=resizes-visual` so the virtual keyboard does not abruptly resize the layout viewport (`window.innerHeight`), allowing `measureKeyboardInsetBottom()` to compute the true keyboard inset (`window.innerHeight - vv.height`) and drive smooth `transition-[padding-bottom]` push animations (`280ms cubic-bezier(0.32, 0.72, 0, 1)`) without layout snapping. Root `html, body, #root` stay locked against viewport panning (`overflow: hidden`, `position: fixed; inset: 0` on `body`, `touch-none` on non-scrollable chrome/composer, `overscroll-contain` + boundary `touchmove` containment on scroll containers, `installViewportScrollLock` resetting `visualViewport.offsetTop` via `documentElement.scrollIntoView`, and `MainActivity.kt` `OVER_SCROLL_NEVER` + `setOnScrollChangeListener`).

## Domain & ADR Consistency

- Use `GLOSSARY.md` terms in UI copy, tests, and PR descriptions (`Owner`, `Bot`, `Topic`, `Homeserver 地址`, `用户名`, `未读`, `已读位置`, `正在回应`, `不可用`).
- Respect layout and interaction contracts in `docs/adr/` (e.g. ADR-0017 avatar-free Topic rows, ADR-0020 unread dot + pinned header, ADR-0021 wide split vs narrow stack, ADR-0026 monochrome semantic tokens). If a change intentionally revises an ADR, state the divergence explicitly and update or supersede the ADR.

## Tests

- Iterate on affected files with `npx vitest run <path>` or `npm run test:unit` (~10s) before running full `npm test` (~38s), `npm run lint`, and `npm run build` prior to pushing.
- In integration tests (`src/waypoint/integration/`), await DOM convergence inside `waitFor(...)` rather than asserting synchronously right after a mock network/sync counter increments.
